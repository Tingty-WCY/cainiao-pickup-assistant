## BUG：中文项目路径导致 `TypeError: Invalid character in header content ["X-React-Native-Project-Root"]`

- 现象：`npm start` 出二维码、手机扫码后终端疯狂刷该 TypeError（Expo Go 2.32.20 / SDK 52 已匹配成功，说明版本问题已解决，卡在 /status 响应）。
- 根因：`node_modules/@expo/cli/build/src/start/server/metro/dev-server/createMetroMiddleware.js` 第 73 行
  `res.setHeader("X-React-Native-Project-Root", metroConfig.projectRoot)`。
  HTTP 头值是 latin1 限定，项目路径 `C:\Users\汀兲宇丶\WorkBuddy\菜鸟驿站` 含中文 → Node 抛错。
- **修复（已改，node_modules 内，重装依赖会丢）**：改为 `res.setHeader("X-React-Native-Project-Root", encodeURI(metroConfig.projectRoot));` 并加注释说明。全仓 Grep 确认仅此一处 setHeader 使用 projectRoot。
- **长期方案**：把项目搬到纯 ASCII 路径（如 `C:\dev\cainiao`，同盘 move 瞬时完成、node_modules 跟着走、不用重装）。
- 教训（跨会话复用）：**Expo 项目路径必须是纯英文/数字**，中文用户名 + 中文目录名会踩这个坑；判断 SDK 是否匹配，看「扫码后是否开始请求 /status」即可，能刷这个错说明版本已经对了。

## BUG：手机端 500 `Unable to resolve module ../../App from node_modules/expo/AppEntry.js`

- 现象：Expo Go 扫码后红屏，bundle 请求 500，报 `Unable to resolve module ./..App from .../node_modules/expo/AppEntry.js`。
- 根因：`package.json` 的 `"main": "node_modules/expo/AppEntry.js"` 是**非 router 项目**的入口，该文件内部 `import '../../App'`，要求项目根有 `App.tsx`；本项目是 expo-router 结构（路由全在 `app/` 下，入口 `app/_layout.tsx`），根目录没有 `App.tsx`。
- **修复**：`"main"` 改为 `"expo-router/entry"`（expo-router 官方入口，存在 `node_modules/expo-router/entry.js` → `entry-classic.js`）。
- 教训（跨会话复用）：**用 expo-router 的项目，package.json 的 main 必须是 `expo-router/entry`**，写 `node_modules/expo/AppEntry.js` 会在真机上以「找不到 App」的形式暴露。
- 注：项目根无 babel.config.js，Expo 零配置 babel 正常工作，未新增（且 package.json 有 `"type":"module"`，新建 .js 配置需写成 ESM，徒增风险）。
