## Bug：手机报 `table packages has no column named tail_number`

- 根因：`ExpoDbClient.init()` **只循环了 `MIGRATIONS`，从没执行 `OPTIONAL_MIGRATIONS`**（`migrations.ts` 里的 `runMigrations()` 定义了但无人调用）。老用户手机上库已存在 → `CREATE TABLE IF NOT EXISTS` 跳过 → 增量列永远加不上。

- 顺手把 `runMigrations` 的 exec 签名改成 `(sql) => Promise<void> | void` 并 `await`。
- **教训：以后新增任何字段，必须在 `ensurePackageColumns()` 的 `needed` 数组里登记一次**，否则老库升级必炸。

## BUG：添加快递崩溃 `NOT NULL constraint failed: packages.status`（已修复）

### 根因（典型的「加字段漏改一处」）
`src/db/expoClient.ts` 的 `createPackage()` 里，INSERT 的**列清单漏了 `box_no`**，但参数数组里有 `input.boxNo ?? null`。结果所有占位符整体错位一格：
- `boxNo` 被写进了 `status` 的位置
- 于是**格口为空时 status 就是 NULL** → 撞上 `status TEXT NOT NULL` 崩溃
- 上一次加 `box_no` 时改了 schema / migrations / OPTIONAL_MIGRATIONS / 参数数组 / UPDATE 语句，**唯独漏了 INSERT 的列表**。

> 注意：`UPDATE` 语句当时是对的，所以只有「新增」会崩，「编辑」不会。

### 修复
- INSERT 列清单补上 `box_no`（15 列 ↔ 15 个值 ↔ 14 个参数）。
- 把 packages 的写入语句抽到新文件 **`src/db/statements.ts`**：`PACKAGE_INSERT_SQL` / `PACKAGE_UPDATE_SQL` / `packageInsertParams()` / `packageUpdateParams()`。抽出来的理由：expoClient 依赖 expo-sqlite 原生模块，vitest 跑不起来，这类「SQL 与参数错位」bug 之前根本测不到。
- `packageInsertParams` 里 status 加运行时兜底 `input.status ?? 'UNKNOWN'`（底层还有建表默认值 `DEFAULT 'UNKNOWN'`，双保险）。
- 新增 `tests/statements.test.ts`（4 例）：按位置把「列名 → 绑定的值」解析出来，断言 `box_no` 拿到 null、`status` 拿到 `'PENDING_PICKUP'`、列数/值数/参数数三者一致。**这是防这一类 bug 复发的关键**。
- 测试 52 → **56**，三绿。

### 教训（已进项目 MEMORY）
**新增/删除任何字段时，必须一次性核对 5 处**：types → schema.ts → migrations.ts（CREATE + OPTIONAL_MIGRATIONS）→ statements.ts（SQL 列清单 / VALUES / 参数数组三者等长同序）→ UI。
**判据：列清单个数 == VALUES 值个数（含字面量 NULL）== 参数数组长度。**

## 新需求：账号页加「跳转淘宝/拼多多」→ 已产出可行性分析

## 修正：`taobao://` 不保证落在首页（用户实测反馈）

用户实测后指出「你打开的也不是首页啊」。核实结论：

- **裸 scheme 由 App 自己决定落点**。只写 `taobao://` 时，淘宝常恢复到「上次退出时停留的页面」或落到「我的淘宝」，**不保证是首页** —— 我之前说「只能打开首页」属表述不严谨。

## 构建失败根因确认：Kotlin 版本冲突（已修）

用户提供了完整日志，决定性的一行是：

```
> Task :expo-modules-core:compileReleaseKotlin
e: This version (1.5.15) of the Compose Compiler requires Kotlin version 1.9.25
   but you appear to be using Kotlin version 1.9.24 which is not known to be compatible.
```

**`expo-modules-core` 带的 Compose 编译器（1.5.15）要求 Kotlin 1.9.25，而 RN 0.76.0 生成的 Android 工程给的是 1.9.24** → `:expo-modules-core:compileReleaseKotlin` 编译失败 → `BUILD FAILED`。
这是 Expo SDK 52 的已知坑（`expo/expo#32844`），**与业务代码无关**，纯环境组合问题。

### 解法（官方推荐，不要手改 native）
- **用 `expo-build-properties` 插件钉死 Kotlin 版本**：`app.json` 的 plugins 加
  `["expo-build-properties", { "android": { "kotlinVersion": "1.9.25" } }]`
  > 手改 `android/build.gradle` 会被 `prebuild` 覆盖掉，必须走 plugin。
- 补上 expo-doctor 报缺的两个 peer 依赖（**不补的话离开 Expo Go 可能崩**）：
  `expo-constants: ~17.0.8`、`expo-linking: ~7.0.5`；新装 `expo-build-properties: ~0.13.3`。
- 保留上一轮改的 `expo-sqlite → ~15.1.4`、`react-native → 0.76.9`。
- `打包说明.md` 第九节已改写为准确根因（之前那版是推测）。

### 教训
- **`Gradle build failed with unknown error` 只是兜底文案**，必须拿到 `Run gradlew` → `* What went wrong:` 附近的真实报错。
- 用户贴的日志有几百行，真正有用的**只有 1 行**（`e: This version (1.5.15) of the Compose Compiler...`），其余全是无关的 deprecation warning。**看构建日志要按关键词定位**（`e:` / `FAILURE` / `What went wrong` / `Caused by`），不要逐行读。

## 紧接着的第二个错误：`expo config --json exited with non-zero code: 1`

用户没跑 `npm install` 就直接 `eas build`，报：

```

```

**原因**：EAS CLI 会**在本地**先跑 `expo config --json` 收集项目信息；该命令解析 `app.json` 时会 require `plugins` 列表里的包。
`expo-build-properties` 只写进了 package.json、**没装进 node_modules** → require 失败 → exit 1 → build 直接终止。

**教训：「写进 package.json」≠「已安装」。** 凡是往 `app.json` 的 `plugins` 里新增包，必须**先装再构建**（`npm install` 或 `npx expo install <包>`）。
快速确认装没装：Glob `node_modules/<包名>/package.json`。

**验证配置能否解析**（比等 20 分钟构建快得多）：

```powershell
npx expo config --json > $null   # 无输出即正常
```
